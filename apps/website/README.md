# Lyra website

The Lyra marketing site, built on the accepted Direction 3 (Resonance): a landing page at `/`, a downloads page at `/download`, and a page for each platform at `/macos`, `/windows` and `/linux`. It is isolated from the Tauri app and shares no runtime code with it.

Built with TypeScript 7, Vite 8, React 19 and TanStack Start (TanStack Router file-based routes and typed search params, rendered on the server and prerendered at build time). Linting is Oxlint with type-aware rules; unit tests run on Vitest.

## Run and verify

From `apps/website` (use Node.js 24 LTS; supported versions are declared in `package.json`):

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 4180 --strictPort
npm run lint        # oxlint, type-aware, warnings fail
npm run typecheck   # tsc -b
npm test            # vitest
npm run build       # vite build, type check
npm run test:sites  # node:test checks for the Sites worker
```

TypeScript 7 has no programmatic API yet, so the toolchain avoids tools that need one (typescript-eslint, for example). Oxlint's type-aware rules run on `oxlint-tsgolint`, which is built on the same native compiler.

QA helpers: `?frame=<phrase>:<seconds>` renders one still frame of the hero light (phrases 0 to 3: treble clef, bass clef, beamed notes, fermata). `0:6.8` shows a complete figure; `2:8.2` shows the beamed notes melting; `0:9.8` shows the empty staff between figures. `?motion=off` starts with the hero paused. In development the engine is exposed as `window.__lyricLight`.

## Structure

| Path | Purpose |
|---|---|
| `src/router.tsx` | `getRouter()` for TanStack Start: scroll restoration, intent preloading, the error page |
| `src/routes/` | File routes: `__root.tsx` (shared head tags, the HTML document, site frame), `index.tsx` (`/`, structured data, QA search params), `download.tsx` (`/download`, `?platform=`), `macos.tsx`, `windows.tsx`, `linux.tsx`, and `$.tsx` (every other address: the not-found page). `src/routeTree.gen.ts` is generated by the Start plugin; do not edit it |
| `src/pages.ts` | Each page's address, title, description and link-preview text; `pageHead()` turns one into route head tags, and `structuredData()` describes the app for search engines |
| `src/hydration.ts` | Hooks for values the server cannot know (the visitor's platform, media queries), which switch over once the page has hydrated |
| `src/hero/lyric-light.ts` | WebGL2 engine: lyric atlas, glass distance fields, refraction, caustics, string simulation, clock, quality fallback |
| `src/hero/phrases.ts` | The four musical figures, authored in staff spaces, and their draw, hold and release timeline |
| `src/hero/lyrics.ts` | Lines from public-domain songs for the hero field, with their sources |
| `src/hero/LyricLightField.tsx` | React wrapper: sizing, visibility, pointer light, still-art fallback without WebGL2 |
| `src/demo/` | Three public-domain demo songs (Shenandoah, Greensleeves, Danny Boy) with artwork palettes, the song clock, and illustrative recreations of the window, Marquee and overlay |
| `src/landing/LandingPage.tsx` | Hero, pinned surfaces story, players picker, settings preview, steps, liner notes, FAQ, closing; interaction animation uses Motion (`motion/react`) |
| `src/download/DownloadPage.tsx` | Platform rows, release status, build from source |
| `src/platform/PlatformPage.tsx` | The macOS, Windows and Linux pages: requirements, installers, install steps |
| `src/errors/` | Not-found and error pages, in the downloads page's style |
| `src/components/` | Site frame, header, footer, external links, download button, staff-line motif (draws in on view, then breathes with a passing glint), OS and player marks |
| `src/site-config.ts` | Production origin; repository, release and installer URLs; platform facts; platform detection |
| `worker/index.js` | Cloudflare Worker: page addresses to prerendered files, unknown addresses to the SPA shell with a 404 status |

The landing route stays in the entry bundle (`codeSplitGroupings: []`) so the hero never waits on a second request; other routes are split automatically. React, the router and Motion build into their own chunks, preloaded alongside the app.

Search params are validated in each route's `validateSearch`. TanStack Router merges validated params over the raw query, so validators return every key (as `undefined` when invalid) to keep a bad value from reaching the page.

## How the hero works

Two layers of lines from public-domain songs drift in a texture atlas, hidden in the dark. A staff of five glass rods runs the full width of the hero on a slow travelling wave, softened behind the copy. It carries four musical figures: treble clef, bass clef, beamed notes and a fermata. On a first visit the field fades up and the staff draws in before the first clef is written. Clefs are written along their strokes; notes swell out of their rods on springs, grow stems, and catch the light as they form. Each figure holds, then melts back into the staff (a clef drains back along its stroke) before the next begins.

A single fragment shader renders the glass in the manner of Apple's Liquid Glass: a slab with a flat, clear face and a narrow rounded rim. Lensing happens only in the rim band, which draws in what lies just past the edge; the face shows the words behind it nearly undistorted and slightly brightened. A crisp specular line runs along the edge, brightest on the side facing the light and on the opposite side, with a soft inner rim light for thickness, and words dim slightly where they pass under the edge so the glass sits above them. Glass thinner than a line of text lets little through. The symbols give off a soft light of their own, and caustics stay faint. Chromatic aberration rests at 6% of its previous strength; the moving glimmer, the tip of the staff as it draws in, and glass as it forms bring it back to full strength where they pass. Clef distance fields are cached per layout; a small CPU string simulation makes the rods ring on note landings, cursor plucks and taps on the staff. The staff stays quieter than the figures, and dimmer away from them. A hand-held light follows fine pointers, and the effects dim behind the hero copy.

The loop pauses when the hero is off screen or the tab is hidden, honours reduced motion with a lit still frame, has a pause control, and falls back to the still Resonance artwork without WebGL2. The decorative field is capped at 1.5× pixel density and lowers resolution in two steps on slow hardware; the HTML copy stays at native resolution. Context restoration rebuilds the GPU resources and resumes the animation.

## Link previews

The root route's `head` carries the shared Open Graph and Twitter tags, and each page's `head` adds its title, description, `og:url` and canonical link from `src/pages.ts`. All addresses are absolute and point at https://lyra.eiselabs.com, on every host. `public/og-image.png` is the 1200×630 share image: a still of the hero at `?frame=0:6.5` (the glimmer crossing the treble clef's notes) with the navigation and buttons hidden and a line about the platforms at the bottom. Remake it at 2× and scale it down after a big change to the hero.

## Rendering and Cloudflare deployment

TanStack Start renders the site with React on the server, and `npm run build` prerenders every static route to `dist/client/<path>/index.html`, so each page's HTML carries its heading, copy and head tags. Crawlers read it without running JavaScript. In the browser React hydrates the page; the glass animation and demos start then. Anything that depends on the visitor (their platform, `?platform=`, reduced motion, the QA search params) renders as the server did and switches over once hydrated (`src/hydration.ts`), so hydration matches the HTML.

The build also writes `sitemap.xml` (every prerendered page except the shell; `lastmod` is the build date), `pages.json` (the same list, from Start), and the SPA shell `_shell.html`: the site frame with an empty page area, which the browser fills in. Its mask path is `/_shell`, not the default `/`, because the shell takes the place of the page at its mask path. `public/robots.txt` points at the sitemap. The home page's structured data takes its `softwareVersion` from `[workspace.package]` in the root `Cargo.toml`; a pre-release version is left out.

`wrangler.jsonc` deploys `worker/index.js` as `lyra-website`, serving **https://lyra.eiselabs.com** with `dist/client` bound to `ASSETS`. The account ID is supplied through `CLOUDFLARE_ACCOUNT_ID` rather than committed to the repository. Page requests run through the Worker, which serves `/download` from `download/index.html`, moves `/download/` to `/download` with a 301, and answers unknown addresses with the SPA shell and a 404 status; the not-found page then renders in the browser. Known static asset paths are served directly. HTML asset redirects and automatic SPA fallback are disabled because the Worker handles fallback itself. Missing files stay 404s. Hosts other than lyra.eiselabs.com (workers.dev, branch previews) get `X-Robots-Tag: noindex`. Workers logs and traces are enabled. The compatibility date stays pinned independently of Wrangler; advance it only after testing runtime changes.

`npm run verify:deployment` checks a running copy the way a crawler sees it: every page in the sitemap must answer 200 with its own title, description, canonical link, heading and copy in the HTML, and the home page must carry its structured data.

From this directory:

```sh
npm ci
npx wrangler login
npx wrangler whoami
export CLOUDFLARE_ACCOUNT_ID="<your-account-id>"
npm run deploy:check    # build, type check, and package without uploading
npm run preview:worker # build and run the real asset Worker locally on :8787
# In another terminal:
npm run verify:deployment
```

`npm run deploy` builds and publishes the Worker and its assets to the account selected by `CLOUDFLARE_ACCOUNT_ID` and the configured custom domain. Find the account ID in the Cloudflare dashboard or `npx wrangler whoami`; it is an identifier, while `CLOUDFLARE_API_TOKEN` is a credential. Keep both values outside the repository. Cloudflare manages the domain's DNS record and TLS certificate. Check the live deployment with `npm run verify:deployment -- https://lyra.eiselabs.com`. Credentials belong in Wrangler's local login or `CLOUDFLARE_API_TOKEN`, never in the repository.

In CI, set `CLOUDFLARE_ACCOUNT_ID` as an environment variable and store `CLOUDFLARE_API_TOKEN` as a secret in the CI provider. See [Wrangler's supported environment variables](https://developers.cloudflare.com/workers/wrangler/system-environment-variables/#supported-environment-variables).

For Cloudflare's Git-connected Workers Builds, use root directory `apps/website`, build command `npm run build`, deploy command `npx wrangler deploy`, and Node.js 24. Connect the intended production branch in Cloudflare; committing this configuration alone does not enable automatic deployments. Do not also enable an independent deployment workflow for the same branch.

Cloudflare keeps **Production** and **Previews Base** build settings separately. In **Previews Base**, also set root directory `apps/website` and build command `npm run build`, with preview command `npx wrangler preview`. The pinned Wrangler version supports Worker Previews, and the empty `previews` block in `wrangler.jsonc` enables branch previews with the same static assets and compatibility settings. See [Cloudflare's preview setup](https://developers.cloudflare.com/workers/previews/get-started/).

Existing branch previews keep their own saved build settings. Select each existing branch from the environment switcher and update **Settings > Builds** to the same root directory, build command and preview command; changing **Previews Base** alone does not update them.

## Downloads and source

`src/site-config.ts` centralises the public repository (`https://github.com/eisewilliam/project-lyra`), the releases page and per-platform binary URLs. The homepage and platform download buttons use GitHub's stable `releases/latest/download/` URLs, so future stable releases keep the same links. The public 0.2.0 installers and `latest.json` were verified without signing in before enabling `releasesPublished`. macOS builds are signed and notarized; Windows installers still carry first-launch SmartScreen advice. Platform requirements and first-launch notes come from the repository README and platform adapters; update `siteConfig.signed` when signing changes.

Lyra is not Spotify-only. `players.named` in `src/site-config.ts` lists the players the site names (Spotify, Apple Music, YouTube Music); the players section, closing note, steps, liner notes, FAQ, platform requirements, downloads and platform pages read from it. Update the page descriptions in `src/pages.ts` alongside it.
