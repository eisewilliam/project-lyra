# Landing site instructions

## Accepted design decisions

- Direction 3, Resonance, is the accepted direction (user naming: direction 1 is Living Score, direction 3 is Resonance). The site is one landing page at `/` plus a downloads page at `/download`. Living Score is retired; its prototype source is archived in `design/archive/2026-10-08-two-direction-prototype/`.
- The hero background is accepted: a procedural WebGL lyric field (`src/hero/`). Original lyrics drift in the background colour and are only visible where a staff-shaped light falls; the light draws a musical figure (bass clef, treble clef, beamed notes, fermata), holds, dims to darkness and starts again. It is never a static image except as the no-WebGL fallback.
- Hero layout: words on the left, the song on the right. Copy is left-aligned to the header's left edge and vertically centred, with Download Lyra and Other downloads side by side. The staff may emerge from behind the copy (dimmed), but every clef, note, barline and fermata renders in the column to the right of the copy. On phones and portrait tablets the light sits above and the copy sits low, still left-aligned, with figures favouring the right half. Do not pin the copy to the top of the hero.
- Buttons carry at most one icon. The primary Download Lyra button shows only the detected platform's icon (a download glyph when unknown). Button heights by role: 54px hero/closing, 46px secondary, 38px header.
- Platform icons are solid brand marks in `src/components/OsIcons.tsx` (Apple and Tux from Simple Icons, Windows as four panes), not Phosphor's outline OS icons. The player-support note lives by the closing CTA and on `/download`, never in the hero.
- Other downloads is its own page (`/download`), not a dialog. The detected platform is listed first and lit; `?platform=` preselects one.
- Lyra is not a Spotify-only product. Copy names Spotify, Apple Music and YouTube Music, then "most players that show up in your computer’s media controls"; it never claims every player. Named players live in `players.named` in `src/site-config.ts` (see `docs/PLAYER_SUPPORT.md`); copy uses `playersAndOthers` / `playersOrOthers`, which format the names and the closing phrase as one British-style list (no doubled "and", no Oxford comma). Adding a player is a data change (also update the static meta description in `index.html`).
- The Players section ("Whatever you play it on.", after the surfaces) is interactive: picking Spotify, Apple Music, YouTube Music in a browser or a video in a browser swaps the Lyra window's demo song and the source mark on its artwork; the video shows Lyra ignoring non-music with "Show lyrics anyway". Player marks are monochrome Simple Icons paths in `src/components/PlayerIcons.tsx`, filled with `currentColor` like the app; never redraw or colour them.
- Visible primary CTA is Download Lyra; communicate the detected desktop OS only through its icon. Keep a small Star on GitHub header action.
- Colour: brand teal and mint belong to Lyra's light and primary actions. Content takes colour from the music: each public-domain demo song in `src/demo/song.ts` has an artwork palette that tints its scenes, and the song accents (`--amber`, `--rose`, `--cobalt` and pale variants in `src/styles.css`) colour the rest of the page where it needs it (step bars, the liner-notes sleeve, settings controls, FAQ markers, the This computer tag). Do not reintroduce brand teal as decoration.
- The surfaces section pins on wide screens (960px and up, 620px tall and up) while about forty percent of a screen of scroll passes per surface. No scroll snapping: the user rejected it. Scroll position picks the surface; the rail fills continuously with scroll and is clickable. Scene changes must be obvious: the old surface lifts away and blurs, the new one rises in from the direction of travel (Motion springs, exits about 0.4s). Smaller screens stack each step with its own scene. Lyric surfaces are always dark and translucent in the app; only Settings has a light theme, so never show a light-theme surface.
- Motion (`motion/react`) handles interaction and transition animation, under `MotionConfig reducedMotion="user"`. Keep motion answering the visitor (scroll, hover, press, selection, opening) plus the single hero entrance; do not add generic fade-up entrances to every section.
- Sections beyond the hero must present the product, not just describe it: the stage recreates Lyra's three surfaces playing an original demo song in sync; settings are tried live; steps sit on a staff as measures; privacy and credits are liner notes.
- Type: Geist only. Upright for interface and headings; italic wherever words are sung (hero field, staff lyrics, liner-note roles). No tracked all-caps eyebrows, no numbering unless the content is a sequence.
- Use only the logo and colours from local branding. Do not use brandboard layouts, typography prescriptions, local mockups, albums or desktop scenes from the brand explorations.
- GitHub will become public later. Public download files are not yet supplied; keep honest pending-release states and centralise destinations and platform facts in `src/site-config.ts`. Demo songs in the product sections are public domain (traditional, or with long-expired copyright, credited in the player); the hero field uses original fragments. Never use lyrics from copyrighted songs, recordings or arrangements.

## Code

- TypeScript 7 (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), Vite 8, React 19, TanStack Router with file routes in `src/routes/`. Do not edit `src/routeTree.gen.ts`; the Vite plugin regenerates it.
- In-site links use TanStack Router's `Link` (hash links as `to="/" hash="faq"`); external links use `ExternalLink`. Read search params and the detected platform through the route (`getRouteApi`), not `window.location` or `navigator`.
- `validateSearch` returns every key, `undefined` when invalid: the router merges validated params over the raw query.
- Keep the landing route in the entry bundle (`codeSplitGroupings: []` in `src/routes/index.tsx`).
- TypeScript 7 has no programmatic API until 7.1, so do not add typescript-eslint or other tools that need it; lint with Oxlint (`npm run lint`, type-aware).
- Before handing work back, run `npm run lint`, `npm test` and `npm run build`.

Run the local server yourself and open the preview in the browser available to this environment. Port 4173 may be taken by another local project; use any free port with `--strictPort`. Do not give the user server-start instructions when you can run it.

When the user gives durable design feedback, preferences or decisions, record them here.

Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs` and `tests/sites-worker.test.mjs` intact so the site can be handed to Sites. The worker's HTML fallback serves `/download`, and unknown paths reach the app's not-found page. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js` and `dist/.openai/hosting.json`.
